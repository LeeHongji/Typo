## 1. 目标与边界

Typo 是一个二维键帽角色（黑色键帽、白色椭圆脸），由用户原画描摹而成，原画和工具在 `design/typo/`。它在一次听写的各个阶段给出反馈：升起、听、想、把文字「按」进输入框。

边界：

- 默认关闭。开关在「设置 → 外观」，键 `tf_typoCompanionEnabled`。
- Typo 不取代录音条。它要么从录音条胶囊上沿探出头，要么站在文本光标旁，同一时刻只出现一个。
- 读不到光标时 Typo 留在录音条上。「站在输入框或窗口角落」的方案在 2026-11-05 按用户要求撤回，不要恢复。
- 只在听写过程中出现。不录音时没有常驻形态。
- 遵守系统「减弱动态效果」：位移和弹跳改为淡入淡出。
- 设置项文案中英双语。

## 2. 分层

代码在 `Sources/Type4Me/UI/Typo/`。

| 层 | 文件 | 职责 |
|---|---|---|
| 几何与绘制 | `TypoReferenceGeometry.swift`、`TypoRenderer.swift` | 描摹轮廓；`TypoExpression` 由眼睛、嘴、气泡符号和手臂姿势组合 |
| 表演 | `TypoPerformance.swift` | 纯值类型状态机：输入事件和时间，输出 `Pose` |
| 身体动作 | `TypoMotion.swift` | `TypoRhythm` 从音量里找音节，`TypoMotion` 用弹簧把音节变成跳、压、歪 |
| 显示 | `TypoSprites.swift` | 每个表情画一次成位图，由 Core Animation 图层移动 |
| 录音条站位 | `TypoCompanion.swift` | `TypoDirector` 把录音条阶段翻译成表演事件；`TypoBuddyView` 负责遮罩 |
| 光标站位 | `TypoCaretStage.swift` | 独立的非激活面板，跟随光标、起跳、落地 |
| 光标定位 | `Services/CaretLocator.swift`、`Services/CaretWatcher.swift` | 通过辅助功能接口读光标矩形；监听应用的光标、文本、焦点通知 |

`TypoPerformance` 不依赖 AppKit 和时钟，所有时间从参数传入，所以每个转场都能在单元测试里按帧复现。两个站位共用同一套表演和位图，只有 `Peek`（下沉深度）不同：录音条上只露头，光标旁全身站出。

## 3. 表演状态机

```text
hidden → entering → listening → thinking → reacting(done | failed | sheepish) → exiting(...) → hidden
```

驱动来源是 `AppState.barPhase`（`FloatingBarPhase`）：

| 录音条阶段 | 表演事件 |
|---|---|
| `preparing`、`recording` | `begin` |
| `finishing`、`processing` | `think` |
| `done` | `react`，按 `FeedbackKind` 和网络状态选表情 |
| `error` | `react(.failed)` |
| `hidden` | `finish` |

退场有四种：

- `success`：小跳、像按键一样压下、沉入。总长控制在录音条 0.3 秒的收起动画之内。
- `leap(offset)`：从站立处翻到新文字旁，压下、回弹、看一眼文字、沉入该行。腾空时间随距离在 0.3–0.6 秒之间变化，远距离会翻跟头。
- `cancelled`：用户取消，难过地沉下。
- `failed`：出错后离开，受惊地沉下。

听的时候：

- 嘴随音量开合；持续大声会炸毛，大声的阈值相对于这位说话人平时的音量。
- `TypoRhythm` 以 25 Hz 的音量计找音节起点，按音节间隔的中位数给每一句选步态：`bounce`（快）、`bob`（稳）、`sway`（慢或轻）。
- 停顿 0.9 秒后休息并偶尔做小动作（张望、双眨眼、瞥、伸懒腰），静 8 秒打瞌睡，再开口时惊醒。
- 对识别出的文字做反应：新词点头，问号出问号气泡，感叹号举手。
- 接住引用或截图卡片时举手、笑眼，肩旁显示数量。

想的时候按等待时长升级：1.5 秒后耐心等，5 秒后看手腕、点脚，9 秒后冒汗。网络断开时把手放到耳边听；只送进部分文字时露出不好意思的表情。

## 4. 光标旁站位

### 4.1 定位

`CaretLocator.locate` 在后台线程查询，超过预算（默认 0.5 秒）返回超时。结果分三类：找到、密码框、不可用。

找到时带一个层级标记，说明矩形来自哪种读法：文本标记范围、选区范围矩形，或输入框起点（空输入框）。Chromium 和 Electron 应用需要先唤醒辅助功能树，首次查询常为空，所以空或超时后 350 毫秒重试一次。读到的矩形要通过合理性检查（尺寸、是否在某块屏幕内）才采用。

密码框、不可用、前台应用是 Type4Me 自身：`TypoPlacement.mode` 回到 `.bar`。

### 4.2 尺寸与位置

- 身高为光标高度的 1.3 倍，限制在 18–30 pt。
- 脚踩在光标底边，站在光标右侧；该行后面还有文字时站到文字之后，不遮字。
- 右侧放不下（超出屏幕或超出输入框）时站到光标左侧。
- 气泡按 1.4 倍绘制，保证小尺寸下符号可辨认。

### 4.3 跟随与起跳

光标移动的含义取决于表演阶段：

| 阶段 | 含义 | 动作 |
|---|---|---|
| `entering`、`listening` | 用户自己在移动光标 | 沿行滑动；换行或距离远时小跳 |
| `thinking`、`reacting`、腾空中 | 文字落地 | 立即起跳；已在空中则平滑改落点 |
| 其余 | — | 忽略 |

重读光标的时机：应用发出辅助功能通知时（最快 30 毫秒一次），以及按阶段轮询——说话时每 1 秒，想的时候每 80 毫秒，腾空和落稳期间每 40 毫秒。轮询是因为输入框变高、换行、滚动都会移动光标却不发通知。

录音条隐藏时如果还没听到光标移动（应用不发通知），再查最多 1 秒；仍没动就原地压下。

说话时只在锁定的输入框内跟随：用户点到别的窗口去截图或引用时，Typo 留在原处。

### 4.4 面板

`TypoCaretPanel` 是无边框、非激活、忽略鼠标的浮动面板，加入所有空间和全屏辅助层。面板大小只覆盖 Typo 当前站位和本次跳跃的弧线。其他应用的浮动面板可能盖住它，所以大约每秒重新置顶一次。

## 5. 性能

矢量逐帧重绘在只是站着呼吸时占用约 15% 的单核。改为位图加图层后，光标旁站立约 1.5%（数据来自提交 `43202eb` 的实测记录）。新增表情或部件时保持「画一次、移动图层」，不要回到逐帧重绘。

## 6. 调试

关键节点写入 `DebugFileLogger`，前缀 `typo caret:`，包括应用包名、定位层级、矩形、落点、腾空时间、落地等待时长。排查某个应用落点不准时先看这些行。

离线看关键帧：`design/typo/stage/README.md` 里的命令用应用自己的 Typo 源码渲染浅色、深色背景下的姿势图。

## 7. 已知限制

- 以下应用的光标读不到或不稳定，Typo 留在录音条：微信、Warp、Discord、Chrome 的部分网页区域（来自提交 `71e7e6d` 的记录，尚未逐个复测）。
- Chromium、Typora 在粘贴后最长约 1 秒内可能报告旧的光标位置。
- 各应用落点尚未做完整的实机验收。
